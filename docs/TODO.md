## From the 2026-08-28 user audit

See `docs/audit/Training-App-Audit-Report.pdf` for the full write-up. Open findings, highest impact first:

- **Plans can't be deleted or renamed** (High) — `PlanDao.deletePlan()` exists and is tested; this is purely a missing UI entry point. Today the only way to tidy the plan list is "Delete all data", which also destroys logged history.
- **Completed workouts can't be reviewed** (High) — every set/rep/weight/RPE/PR is written on Finish, but nothing reads it back. Suggested: tapping a green-check day on the calendar opens that session's log (`getLogsForPlanSession` + `getLoggedSetsForSessionLog` already return everything needed).
- **Calendar's empty state is misleading** (Medium) — `_selectedDay` starts null, so it says "No sessions on this day" before any day is picked, even when today has a session marker. Default the selection to today.
- **Abandoning a session silently discards it** (Medium) — sets live in memory until Finish. This mattered less before the floating rest timer; now the app actively invites leaving mid-session. At minimum warn on back-navigation.
- **Library exercises can't be edited or deleted** (Medium) — creation captures the full schema but nothing can be corrected afterwards. `ExerciseDao.deleteExercise()` exists, unused.
- **Progression advice ignores the lbs setting** (Medium) — `progression.dart`'s `formatWeight()` hard-codes "kg" and does no conversion, so a user training in pounds gets a number in the wrong unit. A correctness bug, not cosmetic.
- **Body measurements are cm-only** (Low) — no imperial option, though bodyweight itself converts.
- **"Any" placeholder day surfaces in the UI** (Low) — imported sessions read "Week 1 • Any • ...".
- **No search inside a large plan** (Low) — the nine-block programme is 30+ sessions in one flat list.

## Audit findings — all resolved (2026-08-29, commit `c042b03`)

Every finding from `docs/audit/Training-App-Audit-Report.pdf` is fixed. The report is kept as a record of the reasoning.

**The deletion model** (the substantial one). Deletion was all-or-nothing: only "Delete all data" worked, so tidying plans cost you your training history. Redesigned around one asymmetry — *plans are cheap, logged workouts are irreplaceable*:
- `Plans.archivedAt` (schemaVersion 4→5) — archive hides a plan losslessly and reversibly, with an undo snackbar rather than a confirmation dialog.
- `PlanDao.getPlanDeletionImpact()` — deletion always states its blast radius in real numbers first ("12 logged workouts, 148 sets, March–August").
- `deletePlanKeepingHistory()` vs `deletePlanAndHistory()` — deleting a plan offers to keep logged workouts; trained sessions are retained as detached tombstones, untrained ones dropped. Destroying history is a separate explicit choice.
- `ExerciseDao.getExerciseUsage()` / `deleteExerciseKeepingHistory()` — exercises show where they're used before deletion and never take logged sets with them.
- `SessionLogDao.deleteSessionLog()` — individual workouts deletable.
- Semantics pinned by 11 tests in `test/data/plan_deletion_test.dart`.

**Body-measurement tracking is now opt-in** (beyond the audit). Tri-state `BodyTracking` preference — `notAsked`/`enabled`/`declined` — so a "no" is remembered and never re-asked. Prompted once on first session start; re-enableable from Settings; turning it off hides the UI without deleting records.

Other fixes: workout history (list + set-by-set detail, reachable from Progress and completed calendar days); progression advice now honours the lbs setting (was a real correctness bug — hard-coded "kg", no conversion); calendar defaults selection to today; unsaved-session warning on back-navigation; plan search; imperial circumferences; "Any" placeholder hidden.

~~**Editing an existing custom exercise in place**~~ **Done (2026-09-03, commit `889247d`)** — `CreateExerciseScreen(existing: ...)` now doubles as the edit form, pre-filled, preserving id/provenance, custom-exercises-only (seed entries are reseeded every launch).

~~**Exercise images**~~ **Done (2026-09-03, commit `889247d`)** — reframed from "bundled stock photos" (blocked on licensing) to **user-supplied attachments**: `file_picker` + `Exercises.imagePath` (schemaVersion 6, filename-only, resolved at display time), shown on the detail screen and editable/removable from the create/edit form. Old images are cleaned up on replace/delete; a missing file (e.g. a backup restored on a different device) renders a fallback icon rather than throwing. Incidentally fixed a pre-existing bug where backup export/import silently dropped `author`/`sourcePlanName`.
